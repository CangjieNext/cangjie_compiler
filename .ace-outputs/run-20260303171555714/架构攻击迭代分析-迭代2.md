## 二、新发现的架构风险

### BUG-14：mi_option_set 运行时调用时机不正确（Medium）

**严重程度**：🟡 Medium  
**发现位置**：`最终设计方案.md:327-330`

#### 缺陷描述

最终设计方案在 `DeleteInstance` 函数中调用 `mi_option_set`：

```cpp
// DeleteInstance 中的调用
mi_option_set(mi_option_reset_delay, 0);
mi_option_set(mi_option_eager_commit_delay, 0);
mi_collect(true);
mi_heap_collect(mi_heap_get_default(), true);
```

**问题**：`mi_option_set` 通常需要在进程启动时或首次分配前调用，在 `DeleteInstance` 中调用可能无效或效果受限。

根据 mimalloc 文档，`mi_option_reset_delay` 控制的是延迟释放的等待时间，应该在进程初始化时设置。

#### 攻击场景

```cpp
// 进程启动后首次分配
int main() {
    // 此时 mi_option_reset_delay 使用默认值（可能有延迟）
    void* p = malloc(1024);  // 使用默认选项
    
    // ... 编译过程 ...
    
    // DeleteInstance 中设置选项
    mi_option_set(mi_option_reset_delay, 0);  // 可能无效或仅影响后续分配
    
    // 之前的分配可能仍然使用旧的延迟策略
}
```

#### 影响范围

- **场景**：所有使用 mimalloc 的编译
- **影响程度**：内存归还效率可能未达预期

#### 修复建议

```cpp
// src/main.cpp
#ifdef CANGJIE_USE_MIMALLOC
static void InitMimallocOptions()
{
    mi_option_set(mi_option_reset_delay, 0);
    mi_option_set(mi_option_eager_commit_delay, 0);
}

// 在 main 函数开头调用
int main(int argc, const char** argv, const char** envp)
{
    InitMimallocOptions();  // 进程启动时设置
    // ...
}
#endif
```

**优先级**：P2

### BUG-15：asyncDeleteInstance 字段不存在（Medium）

**严重程度**：🟡 Medium  
**发现位置**：`最终设计方案.md:356-357`

#### 缺陷描述

最终设计方案中的同步析构代码引用了 `driverOptions->asyncDeleteInstance`：

```cpp
#else
    // 默认行为：支持异步析构
    if (driverOptions->asyncDeleteInstance) {
        std::thread([instance]() { DeleteInstance(instance); }).detach();
    } else {
        DeleteInstance(instance);
    }
#endif
```

**问题**：查看当前 `Driver.cpp` 代码，`driverOptions` 中不存在 `asyncDeleteInstance` 字段。当前实现是：

```cpp
// Driver.cpp:207（当前代码）
std::future<bool> future = std::async(DeleteInstance, instance);
bool res = InvokeCompileToolchain();
future.get();
```

当前代码始终使用异步析构，没有开关控制。

#### 攻击场景

```cpp
// 设计方案中的代码无法编译
if (driverOptions->asyncDeleteInstance) {  // 编译错误：字段不存在
    // ...
}
```

#### 影响范围

- **场景**：实现阶段
- **影响程度**：代码无法编译，需要调整实现

#### 修复建议

```cpp
// 方案 1：简化实现，不引入新字段
#ifdef CANGJIE_USE_MIMALLOC
    // mimalloc 启用时：同步析构
    DeleteInstance(instance);
    bool res = InvokeCompileToolchain();
#else
    // 默认行为：异步析构
    std::future<bool> future = std::async(DeleteInstance, instance);
    bool res = InvokeCompileToolchain();
    future.get();
#endif
```

**优先级**：P1（实现阶段必须修复）

### BUG-16：首次构建必须联网（Medium）

**严重程度**：🟡 Medium  
**发现位置**：`最终设计方案.md:139-156`

#### 缺陷描述

最终设计方案使用 `execute_process` 自动克隆：

```cmake
if(NOT EXISTS ${MIMALLOC_SOURCE_DIR}/CMakeLists.txt)
    execute_process(
        COMMAND ${GIT_EXECUTABLE} clone --depth 1 --branch ${MIMALLOC_GIT_TAG}
                ${MIMALLOC_GIT_REPO} ${MIMALLOC_SOURCE_DIR}
        ...
    )
endif()
```

**问题**：仲裁评审报告明确要求"离线构建是内网 CI 的硬性要求"，但此方案在首次构建时必须联网。

与 Git submodule 方案对比：
- **Git submodule**：可以在有网络时初始化，后续离线构建
- **execute_process clone**：首次 CMake 配置时必须有网络

#### 攻击场景

```bash
# 内网 CI 环境（无外网访问）
cd /path/to/cangjie_compiler
mkdir build && cd build
cmake -DCANGJIE_USE_MIMALLOC=ON ..

# 错误：
# CMake Error: Failed to clone mimalloc
# fatal: unable to access 'https://gitcode.com/...': Could not resolve host
```

#### 影响范围

- **场景**：内网 CI/CD 首次构建
- **影响程度**：构建失败，需要手动克隆

#### 修复建议

**方案 1**：保留自动克隆，但提供预置目录说明

```markdown
## 内网环境构建

在内网环境中，请预先克隆 mimalloc：

```bash
# 在有网络的机器上
git clone --depth 1 --branch v2.1.7 \
    https://gitcode.com/GitHub_Trending/mi/mimalloc.git \
    cangjie_compiler/third_party/mimalloc

# 打包传输到内网
tar czf cangjie_with_mimalloc.tar.gz cangjie_compiler/
```
```

**方案 2**：回退到 Git submodule（仲裁评审建议）

```bash
git submodule update --init third_party/mimalloc
```

**优先级**：P1

### BUG-17：mi_process_init 缺失导致 Windows 方案 B 初始化不确定（Medium）

**严重程度**：🟡 Medium  
**发现位置**：`最终设计方案.md:370-386`

#### 缺陷描述

最终设计方案的 Windows 入口点配置：

```cpp
// src/main.cpp
#ifdef CANGJIE_USE_MIMALLOC
// 必须在所有其他头文件之前包含
#include <mimalloc-new-delete.h>
#endif
```

**问题**：`mimalloc-new-delete.h` 仅替换 `operator new/delete`，但不保证 mimalloc 在所有分配前初始化。mimalloc 官方文档建议在 Windows 静态链接场景下显式调用 `mi_process_init()`。

#### 攻击场景

```cpp
// 全局对象构造函数
class GlobalConfig {
    std::string path;  // 构造时调用 operator new
public:
    GlobalConfig() { path = "config.toml"; }
};

GlobalConfig g_config;  // 全局对象

int main() {
    // g_config 构造可能早于 mimalloc 初始化
    // 如果使用 MI_SECURE 模式，可能导致初始化检查失败
}
```

#### 影响范围

- **平台**：Windows（方案 B）
- **场景**：有全局对象的编译
- **影响程度**：潜在初始化顺序问题

#### 修复建议

```cpp
// src/main.cpp
#ifdef CANGJIE_USE_MIMALLOC
#include <mimalloc.h>
#include <mimalloc-new-delete.h>

// Windows 平台显式初始化
#if defined(_WIN32)
struct MimallocInit {
    MimallocInit() { mi_process_init(); }
};
static MimallocInit g_mimallocInit;  // 静态对象，在 main 前构造
#endif
#endif
```

**优先级**：P2
