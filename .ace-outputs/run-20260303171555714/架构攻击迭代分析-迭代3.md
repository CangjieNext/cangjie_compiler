## 三、新发现的架构风险

### BUG-19：MimallocInit 静态对象与全局对象构造顺序不确定（Low）

**严重程度**：🟢 Low  
**发现位置**：`最终设计方案.md:319-322`

#### 缺陷描述

设计方案添加了 `MimallocInit` 静态对象来确保 mimalloc 初始化：

```cpp
struct MimallocInit {
    MimallocInit() { mi_process_init(); }
};
static MimallocInit g_mimallocInit;
```

**问题**：C++ 标准不保证同一翻译单元内静态对象的构造顺序（跨翻译单元更是如此）。如果有另一个静态对象在构造时使用 mimalloc 分配内存，可能发生在 `g_mimallocInit` 构造之前。

#### 攻击场景

```cpp
// 假设某个头文件中定义的全局对象
class SomeGlobal {
    std::string data;  // 构造时可能调用 operator new
public:
    SomeGlobal() { data = "initialized"; }
};

// 在某个 .cpp 文件中
static SomeGlobal g_someGlobal;  // 静态对象

// main.cpp 中
static MimallocInit g_mimallocInit;  // 另一个静态对象

// 问题：g_someGlobal 和 g_mimallocInit 的构造顺序不确定
// 如果 g_someGlobal 先构造，其内存分配可能发生在 mi_process_init 之前
```

#### 影响评估

**实际风险较低**，原因：
1. `mi_process_init` 在 mimalloc 静态库内部已有自动初始化机制
2. `mimalloc-new-delete.h` 中的 `operator new` 实现会自动初始化
3. 仓颉编译器代码中全局对象较少，且多为简单初始化

#### 修复建议

这是防御性编程，不是必须修复。如果需要进一步降低风险：

```cpp
// 方案：使用编译器属性确保初始化顺序（GCC/Clang）
__attribute__((init_priority(101)))
static MimallocInit g_mimallocInit;

// 或者：在 operator new 中添加延迟初始化
void* operator new(size_t size) {
    static bool initialized = false;
    if (!initialized) {
        mi_process_init();
        initialized = true;
    }
    return mi_malloc(size);
}
```

**优先级**：P3（可接受，不需要立即修复）

### BUG-20：InitMimallocOptions 与首次分配的竞态（Low）

**严重程度**：🟢 Low  
**发现位置**：`最终设计方案.md:327-331`

#### 缺陷描述

```cpp
int main(int argc, const char** argv, const char** envp)
{
#ifdef CANGJIE_USE_MIMALLOC
    InitMimallocOptions();  // 设置选项
#endif
    // ...
}
```

**问题**：`InitMimallocOptions` 在 `main` 函数开头调用，但全局对象的构造函数在 `main` 之前执行。如果全局对象构造时发生内存分配，此时 `mi_option_set` 尚未调用。

#### 影响评估

**实际风险很低**：
1. `mi_option_set` 设置的是 `reset_delay` 和 `eager_commit_delay`，这些选项仅影响内存归还行为，不影响正确性
2. 即使在 `main` 之后设置，对后续分配仍然有效
3. 仓颉编译器的全局对象很少，且分配量小

#### 修复建议

无需修复。当前方案已经足够好。

**优先级**：P4（可忽略）

---

### BUG-21：多入口点初始化一致性（Low）

**严重程度**：🟢 Low  
**发现位置**：`最终设计方案.md:349-363`

#### 缺陷描述

设计方案要求所有入口点（main.cpp、main-frontend.cpp、main-macrosrv.cpp、main-chir-dis.cpp）都需要相同的初始化配置：

```cpp
// 每个入口点都需要
#ifdef CANGJIE_USE_MIMALLOC
#include <mimalloc.h>
#if defined(_WIN32)
#include <mimalloc-new-delete.h>
struct MimallocInit { MimallocInit() { mi_process_init(); } };
static MimallocInit g_mimallocInit;
#endif
#endif
```

**问题**：代码重复，可能遗漏某个入口点，导致不一致行为。

#### 影响评估

- **当前影响**：无（设计文档已明确列出所有入口点）
- **维护风险**：新增入口点时可能遗漏

#### 修复建议

抽取为共享头文件：

```cpp
// src/cangjie/MimallocInit.h
#pragma once

#ifdef CANGJIE_USE_MIMALLOC
#include <mimalloc.h>

#if defined(_WIN32)
#include <mimalloc-new-delete.h>
struct MimallocInit { MimallocInit() { mi_process_init(); } };
static MimallocInit g_mimallocInit;
#endif

static inline void InitMimallocOptions() {
    mi_option_set(mi_option_reset_delay, 0);
    mi_option_set(mi_option_eager_commit_delay, 0);
}
#endif
```

**优先级**：P3（实施阶段处理）
