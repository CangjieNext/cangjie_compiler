## 背景介绍

### 为什么需要优化内存分配器

仓颉编译器作为一款现代编程语言编译器，在编译过程中需要进行大量的内存分配操作：

1. **AST 节点分配**：词法分析和语法分析阶段创建大量 AST 节点（Token、Decl、Expr、Stmt 等）
2. **符号表管理**：语义分析阶段构建和维护符号表，包含大量字符串和哈希表操作
3. **中间表示（CHIR）**：生成和优化中间表示时需要分配大量 IR 节点
4. **LLVM 后端**：LLVM 内部同样有大量内存分配需求

当前仓颉编译器使用系统默认的内存分配器（Linux 下为 glibc malloc，Windows 下为 CRT malloc）。在大型项目编译场景下，我们发现：

| 问题 | 表现 | 影响 |
|------|------|------|
| 分配延迟高 | 小对象频繁分配导致锁竞争 | 编译时间长 |
| 内存碎片化 | 长时间编译后 RSS 难以释放 | 内存占用高 |
| 多核扩展性差 | 并行编译时性能提升不明显 | 资源利用率低 |

根据 Clang/LLVM 社区的实践（2022 LLVM Dev Meeting），更换高性能内存分配器可带来 **8-15%** 的编译时间提升。

## mimalloc 详细介绍

### 什么是 mimalloc

**mimalloc**（Micro-malloc）是微软研究院开发的一款高性能通用内存分配器，于 2019 年开源，采用 MIT 许可证。

- **GitHub**：https://github.com/microsoft/mimalloc
- **当前版本**：v2.1.7
- **许可证**：MIT License（与 Apache-2.0 兼容）
- **支持平台**：Windows、Linux、macOS、FreeBSD、iOS、Android、WebAssembly

### 核心设计理念

mimalloc 的设计目标是提供**高性能**、**低碎片**、**可预测的延迟**：


### 关键技术特性

| 特性 | 描述 | 性能影响 |
|------|------|---------|
| **Thread-Local Heaps** | 每个线程拥有独立的堆，无锁分配 | 多线程性能提升 20-40% |
| **Segment-based** | 按 4MB segment 组织内存，批量归还 | 内存归还效率提升 |
| **Free-list Sharding** | 每个 size class 有多个 free-list | 减少锁竞争 |
| **Eager Page Return** | 支持立即归还空闲页给 OS | 降低 RSS 峰值 |
| **First-fit with Binning** | 快速查找合适大小的内存块 | 分配延迟降低 |

## 二、技术方案

### 2.1 方案概述

采用**方案 A（全局链接层替换）+ 方案 B（Windows 备选）**的混合策略：

| 平台 | 方案 | 替换范围 | 预期收益 |
|------|------|---------|---------|
| Linux x86-64 | 方案 A | 全局 malloc/free + new/delete | 10-15% |
| Linux ARM64 | 方案 A | 全局 malloc/free + new/delete | 10-15% |
| macOS ARM64 | 方案 A | 全局 malloc/free + new/delete | 10-15% |
| Windows x86-64 | 方案 B | 仅 C++ new/delete | 5-8% |

### 2.2 方案 A：全局链接层替换（Linux/macOS）

#### 2.2.1 工作原理

通过链接器符号覆盖机制，将 `malloc`/`free`/`realloc`/`calloc` 等标准分配函数替换为 mimalloc 实现：

```
┌─────────────────────────────────────────────────────────────┐
│                    仓颉编译器进程                              │
│                                                             │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
│  │  Lexer   │  │  Parser  │  │   Sema   │  │  CHIR    │   │
│  │  new/del │  │  new/del │  │  new/del │  │  new/del │   │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘   │
│       └──────────────┴──────────────┴──────────────┘        │
│                              │                              │
│                    ┌─────────▼──────────┐                   │
│                    │   mimalloc 库       │  ← 链接层替换      │
│                    │  mi_malloc/mi_free  │                   │
│                    │  (覆盖 malloc/free) │                   │
│                    └─────────┬──────────┘                   │
│                              │                              │
│                    ┌─────────▼──────────┐                   │
│                    │    操作系统内存      │                   │
│                    └────────────────────┘                   │
└─────────────────────────────────────────────────────────────┘
```

#### 2.2.2 实现配置

```cmake
# Linux/macOS 平台配置
if(NOT WIN32)
    set(MI_OVERRIDE ON CACHE BOOL "Override malloc/free" FORCE)
    set(CANGJIE_MIMALLOC_STRATEGY "global" CACHE STRING "" FORCE)
endif()
```

### 2.3 方案 B：进程级 new/delete 替换（Windows）

#### 2.3.1 工作原理

仅在可执行文件入口点包含 `mimalloc-new-delete.h`，替换 C++ `operator new/delete`，保留 LLVM 使用系统分配器：

```
┌─────────────────────────────────────────────────────────────┐
│                    仓颉编译器进程                              │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              仓颉前端（C++ new/delete）                │   │
│  │         mimalloc operator new/delete                  │   │
│  └──────────────────────────────────────────────────────┘   │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              LLVM 后端（保持系统分配器）               │   │
│  │              系统 malloc/free                         │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

#### 2.3.2 实现配置

```cmake
# Windows 平台配置
if(WIN32)
    set(MI_OVERRIDE OFF CACHE BOOL "Do not override malloc/free" FORCE)
    set(CANGJIE_MIMALLOC_STRATEGY "new-delete" CACHE STRING "" FORCE)
endif()
```

## 三、依赖管理

### 3.1 mimalloc 源码获取

采用**自动检测 + Git Clone**策略：

```cmake
# cmake/optional/CangjieMimalloc.cmake

set(MIMALLOC_SOURCE_DIR ${CMAKE_SOURCE_DIR}/third_party/mimalloc)
set(MIMALLOC_GIT_REPO "https://gitcode.com/GitHub_Trending/mi/mimalloc.git")
set(MIMALLOC_GIT_TAG "v2.1.7")
set(MIMALLOC_MIN_VERSION "2.0.0")

if(CANGJIE_USE_MIMALLOC)
    # 自动检测目录是否存在
    if(NOT EXISTS ${MIMALLOC_SOURCE_DIR}/CMakeLists.txt)
        message(STATUS "mimalloc source not found, cloning from ${MIMALLOC_GIT_REPO}...")
        find_package(Git REQUIRED)
        execute_process(
            COMMAND ${GIT_EXECUTABLE} clone --depth 1 --branch ${MIMALLOC_GIT_TAG}
                    ${MIMALLOC_GIT_REPO} ${MIMALLOC_SOURCE_DIR}
            RESULT_VARIABLE MIMALLOC_CLONE_RESULT
            OUTPUT_VARIABLE MIMALLOC_CLONE_OUTPUT
            ERROR_VARIABLE MIMALLOC_CLONE_ERROR
        )
        if(NOT MIMALLOC_CLONE_RESULT EQUAL 0)
            message(FATAL_ERROR
                "Failed to clone mimalloc:\n${MIMALLOC_CLONE_ERROR}\n"
                "Please manually clone: git clone --depth 1 --branch ${MIMALLOC_GIT_TAG} "
                "${MIMALLOC_GIT_REPO} ${MIMALLOC_SOURCE_DIR}")
        endif()
        message(STATUS "mimalloc cloned successfully to ${MIMALLOC_SOURCE_DIR}")
    endif()

    # 构建配置
    add_subdirectory(${MIMALLOC_SOURCE_DIR} ${CMAKE_BINARY_DIR}/mimalloc EXCLUDE_FROM_ALL)
endif()
```

```cmake
if(NOT _LSAN_POS EQUAL -1)

endif()

# 互斥处理

    message(WARNING
        "CANGJIE_USE_MIMALLOC is disabled due to ${MIMALLOC_CONFLICT_REASON}. "
        "mimalloc is not compatible with Sanitizers.")
    set(CANGJIE_USE_MIMALLOC OFF CACHE BOOL "" FORCE)
    return()
endif()
```

## 六、内存归还策略

### 6.1 DeleteInstance 实现

```cpp
// src/Driver/Driver.cpp

#include "cangjie/Driver/Driver.h"

#ifdef __linux__
#include <malloc.h>
#endif

#ifdef CANGJIE_USE_MIMALLOC
#include <mimalloc.h>
#endif

bool DeleteInstance(DefaultCompilerInstance* instance)
{
    Utils::ProfileRecorder recorder("DeleteInstance", "CompleteTime");

    // 析构实例
    delete instance;

    // 内存归还
#if defined(__linux__) || defined(__APPLE__)
#ifdef CANGJIE_USE_MIMALLOC
    // 增强型内存归还组合
    // 注意：mi_option_set 已在 main 中设置
    mi_collect(true);                               // 收集所有线程的延迟释放队列
    mi_heap_collect(mi_heap_get_default(), true);   // 强制收集默认堆
#else
    #if defined(__linux__) && !defined(__ohos__)
    (void)malloc_trim(0);
    #endif
#endif
#endif

    return true;
}
```

### 6.2 同步析构策略

mimalloc 启用时**强制同步析构**，消除跨线程竞态风险：

```cpp
// src/Driver/Driver.cpp（调用点）

#ifdef CANGJIE_USE_MIMALLOC
    // mimalloc 启用时：同步析构
    // 原因：mi_collect(true) 跨线程收集存在 TOCTOU 竞态窗口
    DeleteInstance(instance);
    bool res = InvokeCompileToolchain();
#else
    // 默认行为：异步析构
    std::future<bool> future = std::async(DeleteInstance, instance);
    bool res = InvokeCompileToolchain();
    future.get();
#endif
```

## 九、架构决策记录（ADR）

### ADR-001：混合策略选择

**状态**：已决策
**背景**：不同平台对全局符号覆盖的支持程度不同
**决策**：Linux/macOS 使用方案 A，Windows 使用方案 B
**理由**：
- 方案 A 在 Linux/macOS 上成熟稳定，性能收益最大化
- 方案 B 在 Windows 上更简单可靠，避免 DLL 边界问题
**后果**：Windows 性能收益（5-8%）低于 Linux/macOS（10-15%）

### ADR-002：同步析构策略

**状态**：已决策
**背景**：异步析构与 `mi_collect(true)` 存在竞态风险
**决策**：mimalloc 启用时强制同步析构
**理由**：
- `mi_collect(true)` 跨线程收集存在 TOCTOU 竞态窗口
- 同步析构彻底消除竞态风险
**后果**：编译时间略增（预计 +0.5-1%），可接受

### ADR-003：动态库链接策略

**状态**：已决策
**背景**：`cangjie-lsp-share` 独立链接 mimalloc 会导致双实例问题
**决策**：`cangjie-lsp-share` 不独立链接 mimalloc，依赖主程序全局符号覆盖
**理由**：避免跨分配器 free 导致的崩溃
**后果**：`cangjie-lsp-share` 作为独立进程运行时无 mimalloc 加速（可接受）

### ADR-004：mimalloc 选项初始化时机

**状态**：已决策
**背景**：`mi_option_set` 在 `DeleteInstance` 中调用可能无效
**决策**：将 `mi_option_set` 移到 `main` 函数开头
**理由**：确保选项在首次分配前生效，最大化内存归还效率
**后果**：选项全局生效，影响所有分配行为

### ADR-005：Windows 显式初始化

**状态**：已决策
**背景**：方案 B 静态链接下全局对象构造时序不确定
**决策**：添加静态初始化对象调用 `mi_process_init`
**理由**：mimalloc 官方文档要求，避免初始化顺序问题
**后果**：确保 Windows 平台稳定性

### ADR-006：mimalloc 源码获取策略

**状态**：已决策
**背景**：内网 CI/CD 环境需要离线构建
**决策**：自动检测 third_party/mimalloc 目录，不存在时自动克隆
**理由**：
- 首次构建支持网络克隆
- 后续构建复用本地源码，支持离线
- 使用 GitCode 镜像，国内访问更快
**后果**：首次构建需要网络，后续构建完全离线

### ADR-007：Sanitizer 互斥范围

**状态**：已决策
**背景**：mimalloc 与 Sanitizer 存在底层冲突
**决策**：检测所有已知 Sanitizer 配置并自动禁用 mimalloc
**理由**：保护调试能力，避免运行时崩溃或误报
**后果**：Sanitizer 构建无 mimalloc 加速，属于预期行为
