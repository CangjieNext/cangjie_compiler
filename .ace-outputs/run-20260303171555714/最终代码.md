# 仓颉编译器 mimalloc 集成完整实现方案

**文档版本**：v1.0
**实现日期**：2026-03-04
**适用范围**：仓颉编译器（cjc）内存分配器优化

---

## 一、概述

本方案实现使用 mimalloc 替代系统默认内存分配器，以提升仓颉编译器的性能。mimalloc 是微软研究院开发的高性能通用内存分配器，采用 MIT 许可证。

### 性能目标

| 指标 | 目标值 |
|------|--------|
| 编译时间 | 提升 9-14% |
| 内存峰值 | 降低 5-10% 或持平 |
| 内存归还效率 | ≥ 50% |

---

## 二、技术方案

### 2.1 混合策略

采用**方案 A（全局链接层替换）+ 方案 B（Windows 备选）**的混合策略：

| 平台 | 方案 | 替换范围 |
|------|------|---------|
| Linux x86-64 | 方案 A | 全局 malloc/free + new/delete |
| Linux ARM64 | 方案 A | 全局 malloc/free + new/delete |
| macOS ARM64 | 方案 A | 全局 malloc/free + new/delete |
| Windows x86-64 | 方案 B | 仅 C++ new/delete |

### 2.2 方案 A：全局链接层替换

通过链接器符号覆盖机制，将 `malloc`/`free` 等标准分配函数替换为 mimalloc 实现。

### 2.3 方案 B：进程级 new/delete 替换

在 Windows 平台，仅替换 C++ `operator new/delete`，保留 LLVM 使用系统分配器。

## 三、CMake 配置

### 3.1 根 CMakeLists.txt

添加选项定义：

```cmake
option(CANGJIE_USE_MIMALLOC
    "Use mimalloc as the default memory allocator for performance improvement"
    OFF)
```

包含 mimalloc 模块：

```cmake
include(cmake/optional/CangjieMimalloc.cmake)
```

### 3.2 CangjieMimalloc.cmake 模块

主要功能：
- 自动检测并克隆 mimalloc 源码
- Sanitizer 互斥检测
- 平台特定配置
- 创建接口库 `cangjie_mimalloc`

### 3.3 src/CMakeLists.txt

为 cjc 添加 mimalloc 链接：

```cmake
# mimalloc integration for cjc
if(CANGJIE_USE_MIMALLOC)
    target_link_libraries(cjc cangjie_mimalloc)
endif()
```

## 五、内存归还策略

### 5.1 DeleteInstance 函数

```cpp
bool DeleteInstance(DefaultCompilerInstance* instance)
{
    delete instance;
#if defined(__linux__) || defined(__APPLE__)
#ifndef __ohos__
#ifdef CANGJIE_USE_MIMALLOC
    mi_collect(true);
    mi_heap_collect(mi_heap_get_default(), true);
#else
    (void)malloc_trim(0);
#endif
#endif
#endif
    return true;
}
```

### 5.2 同步析构策略

mimalloc 启用时使用同步析构，避免跨线程竞态：

```cpp
#ifdef CANGJIE_USE_MIMALLOC
    DeleteInstance(instance);
    bool res = InvokeCompileToolchain();
#else
    std::future<bool> future = std::async(DeleteInstance, instance);
    bool res = InvokeCompileToolchain();
    future.get();
#endif
```
