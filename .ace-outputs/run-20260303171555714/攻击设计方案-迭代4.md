+ ## 背景介绍
+ 
+ ### 为什么需要优化内存分配器
+ 
+ 仓颉编译器作为一款现代编程语言编译器，在编译过程中需要进行大量的内存分配操作：
+ 
+ 1. **AST 节点分配**：词法分析和语法分析阶段创建大量 AST 节点（Token、Decl、Expr、Stmt 等）
+ 2. **符号表管理**：语义分析阶段构建和维护符号表，包含大量字符串和哈希表操作
+ 3. **中间表示（CHIR）**：生成和优化中间表示时需要分配大量 IR 节点
+ 4. **LLVM 后端**：LLVM 内部同样有大量内存分配需求
+ 
+ 当前仓颉编译器使用系统默认的内存分配器（Linux 下为 glibc malloc，Windows 下为 CRT malloc）。在大型项目编译场景下，我们发现：
+ 
+ | 问题 | 表现 | 影响 |
+ |------|------|------|
+ | 分配延迟高 | 小对象频繁分配导致锁竞争 | 编译时间长 |
+ | 内存碎片化 | 长时间编译后 RSS 难以释放 | 内存占用高 |
+ | 多核扩展性差 | 并行编译时性能提升不明显 | 资源利用率低 |
+ 
+ 根据 Clang/LLVM 社区的实践（2022 LLVM Dev Meeting），更换高性能内存分配器可带来 **8-15%** 的编译时间提升。
+ 
+ ---

+ ## mimalloc 详细介绍
+ 
+ ### 什么是 mimalloc
+ 
+ **mimalloc**（Micro-malloc）是微软研究院开发的一款高性能通用内存分配器，于 2019 年开源，采用 MIT 许可证。
+ 
+ - **GitHub**：https://github.com/microsoft/mimalloc
+ - **当前版本**：v2.1.7
+ - **许可证**：MIT License（与 Apache-2.0 兼容）
+ - **支持平台**：Windows、Linux、macOS、FreeBSD、iOS、Android、WebAssembly
+ 
+ ### 核心设计理念
+ 
+ mimalloc 的设计目标是提供**高性能**、**低碎片**、**可预测的延迟**：
+ 
+ ```

+ │   │                    (进程级全局堆)                              │   │
+ │   └─────────────────────────────────────────────────────────────┘   │
+ │                              │                                      │
+ │   ┌──────────────────────────┼──────────────────────────────────┐   │
+ │   │                          ▼                                    │   │
+ │   │   ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │   │
+ │   │   │ Thread 1    │  │ Thread 2    │  │ Thread N    │  ...    │   │
+ │   │   │ Local Heap  │  │ Local Heap  │  │ Local Heap  │         │   │

+ │   │   │ Segments    │  │ Segments    │  │ Segments    │         │   │
+ │   │   │ (4MB 内存块) │  │ (4MB 内存块) │  │ (4MB 内存块) │         │   │

+ ### 关键技术特性
+ 
+ | 特性 | 描述 | 性能影响 |
+ |------|------|---------|
+ | **Thread-Local Heaps** | 每个线程拥有独立的堆，无锁分配 | 多线程性能提升 20-40% |
+ | **Segment-based** | 按 4MB segment 组织内存，批量归还 | 内存归还效率提升 |
+ | **Free-list Sharding** | 每个 size class 有多个 free-list | 减少锁竞争 |
+ | **Eager Page Return** | 支持立即归还空闲页给 OS | 降低 RSS 峰值 |
+ | **First-fit with Binning** | 快速查找合适大小的内存块 | 分配延迟降低 |
+
