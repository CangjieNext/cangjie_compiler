## 迭代2新发现缺陷仲裁

### ✅ 确认

**BUG-14（mi_option_set 调用时机）** — **确认，P2**

`mi_option_set(mi_option_reset_delay, 0)` 在 `DeleteInstance` 中调用，应在 `main` 开头设置才能影响所有分配。有技术依据，但不阻塞合并。

**BUG-15（asyncDeleteInstance 字段不存在）** — **确认，P1**

设计方案的 `driverOptions->asyncDeleteInstance` 字段在当前代码中不存在，代码无法编译。这是**实现阻塞问题**，必须修复。简化方案：直接使用 `#ifdef` 分支，不引入新字段。

**BUG-17（Windows 缺少 mi_process_init）** — **确认，P2**

Windows 静态链接场景下，全局对象构造可能早于 mimalloc 初始化。mimalloc 官方文档建议显式调用 `mi_process_init()`。需添加静态初始化对象。

**BUG-18（macOS mi_collect 范围遗漏）** — **确认，P3**

增量编译场景未被覆盖，但仓颉编译器当前不支持增量编译。降级为 P3，实施阶段评估。

### ⚠️ 部分确认

**BUG-16（首次构建必须联网）** — **部分确认，P2**

迭代1仲裁建议使用 Git submodule，当前方案未完全采纳，改为自动克隆 + 手动预置提示。

**仲裁立场**：折中方案可接受，理由：
1. Git submodule 会增加仓库体积
2. 当前方案支持"首次联网，后续离线"
3. 内网 CI 可通过预置目录解决

**后果**：需要在文档中明确说明内网环境预置步骤。
