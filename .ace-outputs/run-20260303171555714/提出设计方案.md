## 三个备选方案

### 方案 A：全局链接层替换（推荐）

通过链接器符号覆盖，将 `malloc`/`free` 全局替换为 mimalloc 实现。**零业务代码修改**，仅需 CMake 配置。

```cmake
# 一行配置启用
cmake -DCANGJIE_USE_MIMALLOC=ON ..
```

- 性能收益：编译时间提升 **10-15%**，内存峰值降低 **5-10%**
- 覆盖范围：所有分配路径（包括 LLVM 内部）
- 适用平台：Linux / macOS

### 方案 B：进程级 new/delete 替换（Windows 备选）

在各可执行文件入口点包含 `mimalloc-new-delete.h`，仅替换 C++ `operator new/delete`，保留 LLVM 使用系统分配器。

- 性能收益：编译时间提升 **5-8%**
- 优势：避免 Windows DLL 边界问题，风险更低
- 适用平台：Windows（方案 A 的补充）

### 方案 C：选择性 STL 分配器（未来优化）

为热点数据结构（AST 节点容器、符号表）提供自定义 `MimallocAllocator<T>`，支持 `mi_heap_t` 隔离堆批量释放。

- 性能收益：有限（仅覆盖显式使用的容器）
- 代码侵入性高，维护成本大
- 定位：方案 A 基础上的精细化补充

## 关键设计决策

**Sanitizer 互斥**：CMake 自动检测，启用 ASan/TSan 时自动禁用 mimalloc，保护调试能力不受影响。

**malloc_trim 适配**：Driver.cpp 中的 `malloc_trim(0)` 替换为 `mi_collect(true)`，语义等价。
