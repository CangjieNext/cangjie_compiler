## 二、问题分析与根因定位

### BUG-02: PerformResultsSaving 返回值被忽略

**根因**: 迭代 2 修复 P0（CJO 丢失）时，在 `PerformASTRelease()` 中添加了 `PerformResultsSaving()` 调用，但未检查返回值。`PerformResultsSaving()` 可能因磁盘写入失败返回 `false`，此时 `resultsSaved` 仍被无条件设为 `true`，导致：
1. 编译器不报错，用户不知道 CJO 保存失败
2. 后续 `SAVE_RESULTS` 阶段因 `resultsSaved == true` 跳过重试

**影响范围**: 两处代码路径：
- `CompilerInstance::PerformASTRelease()` (CompilerInstance.cpp:530-532)
- `IncrementalCompilerInstance::PerformASTRelease()` (IncrementalCompilerInstance.cpp:482-484)

### VULN-01: ClearImportedPackages 残留悬垂 AST 指针

**根因**: `CjoManager::ClearImportedPackages()` 只清空了 `importedPackages`（释放 `OwnedPtr<AST::Package>` 所有权）和 `info->pkg`，但 `PackageInfo` 中的其他 AST 指针字段未清理：
- `pkgDecl` — `OwnedPtr<AST::PackageDecl>`，持有 AST 节点所有权
- `exportIDDeclMap` — `Ptr<AST::Decl>` 值，指向已释放的 AST 节点
- `declMap` — `AST::OrderedDeclSet`，内含 AST Decl 指针
- `implicitDeclMap` — `Ptr<AST::Decl>` 值

此外，`ImportManager::ClearASTReferences()` 也不够彻底。ImportManager 的私有成员中有多个 AST 指针持有者：
- `fileImportedDeclsMap` — 持有 `AST::OrderedDeclSet`
- `fileUsedMacroDeclsMap` — 持有 `Ptr<const AST::Decl>`
- `importedDeclsMap` — 持有 `AST::OrderedDeclSet`
- `astWriters` — 持有 `Ptr<const AST::Package>` 键
- `directMacroDeps` — 持有 `Ptr<AST::Package>`
- `declsImportedByNodeMap` / `declToTypeAlias` — 持有 AST 指针
- `dependencyGraph` — 内部缓存持有 `Ptr<AST::PackageDecl>`

### ISSUE-03: 单元测试问题

**根因**: 原测试文件使用了错误的构造函数签名（`TypeManager(diag, opts)` 和 `ImportManager(diag, opts, typeManager, cjoManager)`），与实际 API 不匹配。缺少对新增公共 API（`PackageCodeGenInfo`、状态访问器、`ImportManager::ClearASTReferences`）的测试。

## 三、修复方案

### 修复 1: PerformResultsSaving 返回值检查

在两处调用点检查返回值，失败时返回 `false` 中止编译，不设置 `resultsSaved = true`：

```cpp
// CompilerInstance::PerformASTRelease()
if (!resultsSaved) {
    if (!PerformResultsSaving()) {
        return false;  // Propagate save failure to abort compilation.
    }
    resultsSaved = true;
}

// IncrementalCompilerInstance::PerformASTRelease()
if (!resultsSaved) {
    if (!PerformResultsSaving()) {
        return false;  // Propagate save failure to abort compilation.
    }
    resultsSaved = true;
}
```

**设计考量**: 保存失败时不设置 `resultsSaved = true`，让 `SAVE_RESULTS` 阶段有机会重试。但由于 `PerformASTRelease()` 返回 `false` 会中止整个编译流水线（`Compile()` 循环 break），实际上 `SAVE_RESULTS` 不会执行。这是正确的行为——保存失败应该中止编译。

### 修复 2: ClearImportedPackages 完整清理

扩展 `CjoManager::ClearImportedPackages()` 清理 `PackageInfo` 的所有 AST 指针字段：

```cpp
void CjoManager::ClearImportedPackages() const
{
    impl->GetImportedPackages().clear();
    for (auto& [name, info] : impl->GetPackageNameMap()) {
        info->pkg = nullptr;
        info->pkgDecl.reset();
        info->exportIDDeclMap.clear();
        info->declMap.clear();
        info->implicitDeclMap.clear();
    }
}
```

扩展 `ImportManager::ClearASTReferences()` 清理所有 AST 指针持有成员：

```cpp
void ClearASTReferences()
{
    curPackage = nullptr;
    cjoManager->ClearImportedPackages();
    fileImportedDeclsMap.clear();
    fileUsedMacroDeclsMap.clear();
    importedDeclsMap.clear();
    astWriters.clear();
    directMacroDeps.clear();
    declsImportedByNodeMap.clear();
    declToTypeAlias.clear();
    if (dependencyGraph) {
        dependencyGraph.reset();
    }
}
```
