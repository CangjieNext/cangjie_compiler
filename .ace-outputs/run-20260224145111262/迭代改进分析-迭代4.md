## 二、问题分析与根因定位

### BUG-03: ASTWriter 内存泄漏

**根因**: `ImportManager::ClearASTReferences()` 中直接调用 `astWriters.clear()` 清空 map，但 `astWriters` 的类型是 `std::unordered_map<Ptr<const AST::Package>, ASTWriter*>`，value 是通过 `new` 分配的裸指针。`std::unordered_map::clear()` 只销毁 map 条目，不会 `delete` 指针指向的对象。

**已有正确实现**: `ImportManager::DeleteASTWriters()` 方法（ImportManager.cpp:564-571）正确地先 `delete` 每个 writer 再 `clear()`：
```cpp
void ImportManager::DeleteASTWriters() noexcept
{
    for (auto& [_, writer] : astWriters) {
        delete writer;
        writer = nullptr;
    }
    astWriters.clear();
}
```

`~ImportManager()` 析构函数（ImportManager.cpp:1525）也正确调用了 `DeleteASTWriters()`。

**影响**: 每次启用 AST 释放的编译都会泄漏所有 `ASTWriter` 对象，泄漏量与导入包数量成正比。

---

## 三、修复方案

单行替换，将 `astWriters.clear()` 改为 `DeleteASTWriters()`：

```cpp
// include/cangjie/Modules/ImportManager.h — ClearASTReferences()
// Before:
astWriters.clear();
// After:
DeleteASTWriters();  // Must delete ASTWriter* before clearing to avoid memory leak.
```

`DeleteASTWriters()` 声明在同一个类的 public 区域（line 347），从 inline 方法调用无问题。
