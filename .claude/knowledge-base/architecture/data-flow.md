# 数据流

- Last Updated: 2026-02-12
- Version: 1.0.0

## 概述

本文档描述仓颉编译器中数据在各模块之间的流转方式。编译过程本质上是一系列数据变换：源代码文本经过逐步转换，最终成为可执行的机器代码。

## 数据流总览

```
源代码文本 (Source Text)
    │
    ▼
Token 流 (Token Stream)
    │
    ▼
抽象语法树 (AST)
    │
    ▼
带类型标注的 AST (Typed AST)
    │
    ▼
仓颉高级 IR (CHIR)
    │
    ▼
LLVM IR
    │
    ▼
目标代码 (Object Code)
    │
    ▼
可执行文件 (Executable)
```

## 各阶段数据变换详解

### 1. 源代码文本 → Token 流

- **执行模块：** Lex
- **输入格式：** UTF-8 编码的源代码字符流
- **输出格式：** Token 序列，每个 Token 包含：
  - TokenKind（类型标识）
  - 文本值（字面量内容）
  - SourceLocation（源码位置：文件、行、列）
- **数据特征：** 线性序列，丢弃了空白符和注释，保留了所有语义相关的词法信息

### 2. Token 流 → AST

- **执行模块：** Parse
- **输入格式：** Token 序列
- **输出格式：** 树形 AST 结构
  - 根节点为编译单元（TranslationUnit）
  - 子节点为声明（Decl）、语句（Stmt）、表达式（Expr）
  - 每个节点保留 SourceLocation
- **数据特征：** 从线性结构转为层次化树形结构，体现了语法嵌套关系
- **副作用：** 宏调用在此阶段被展开（Macro 模块介入），条件编译指令被处理

### 3. AST → Typed AST

- **执行模块：** Sema
- **输入格式：** 未标注类型的 AST
- **输出格式：** 带类型标注的 AST，额外包含：
  - 每个表达式节点的推断类型
  - 标识符到声明的绑定关系
  - 重载决议结果
  - 泛型实例化信息
- **数据特征：** 树形结构不变，但节点被丰富了语义信息
- **外部数据流入：**
  - Modules 模块提供导入包的符号信息
  - Mangle 模块提供符号修饰名称

### 4. Typed AST → CHIR

- **执行模块：** CHIR
- **输入格式：** 带类型标注的 AST
- **输出格式：** CHIR（Cangjie High-level IR）
  - 比 AST 更接近执行语义的中间表示
  - 保留高级语言信息但简化了语法糖
- **数据特征：** 从树形结构转为更扁平的 IR 形式，高级语言构造被降级为更基础的操作
- **优化：** CHIR 层级的优化 Pass 在此阶段执行

### 5. CHIR → LLVM IR

- **执行模块：** CodeGen
- **输入格式：** 优化后的 CHIR
- **输出格式：** LLVM IR（SSA 形式）
  - LLVM Module 包含全局变量和函数定义
  - 每个函数由基本块（BasicBlock）组成
  - 每个基本块包含 LLVM 指令序列
- **数据特征：** 从仓颉特定的 IR 转为通用的 LLVM IR，丢失了大部分高级语言信息
- **外部数据流入：** Mangle 模块提供修饰后的符号名称

### 6. LLVM IR → 目标代码

- **执行模块：** LLVM Backend
- **输入格式：** LLVM IR
- **输出格式：** 目标平台的目标文件（.o）
- **数据特征：** 从平台无关的 IR 转为平台特定的机器代码

### 7. 目标代码 → 可执行文件

- **执行模块：** 链接器（由 Driver 调用）
- **输入格式：** 目标文件 + 运行时库
- **输出格式：** 可执行文件或共享库
- **数据特征：** 多个目标文件和库被合并为单一可执行文件

## 支撑系统的数据流

### Macro（宏系统）

```
宏调用 Token → Macro 模块 → 展开后的 Token 流 → 重新解析为 AST
```

宏展开发生在 Parse 阶段，展开结果被重新注入 Token 流并解析。

### Modules（模块系统）

```
import 语句 → Modules 模块 → 外部包的符号表 → 注入 Sema 的作用域
```

模块系统在 Sema 阶段提供外部包的类型和符号信息。

### IncrementalCompilation（增量编译）

```
上次编译缓存 + 变更文件列表 → 增量编译模块 → 需要重编译的最小文件集
```

增量编译系统通过依赖分析确定最小重编译范围，跨越多个编译阶段管理缓存。

### Driver（驱动器）

```
命令行参数 → Driver → 编译选项 → 协调各阶段执行 → 最终输出
```

Driver 不直接参与数据变换，但控制数据在各阶段之间的流转顺序和方式。

## 错误数据流

诊断信息（错误、警告）在各阶段产生，统一收集后报告给用户：

```
各阶段 → DiagnosticEngine → 格式化输出 → 用户终端
```

每条诊断信息携带 SourceLocation，使用户能够定位问题源码位置。
