# 编译流程管线

- Last Updated: 2026-02-12
- Version: 1.0.0

## 概述

仓颉编译器的编译管线由六个核心阶段组成，每个阶段接收上一阶段的输出并产生下一阶段的输入。完整流程如下：

```
Source Code → Lex → Parse → Sema → CHIR → CodeGen → LLVM Backend → Executable
```

## 阶段详解

### 1. Lex（词法分析）

- **输入：** 源代码文本（UTF-8 字符流）
- **输出：** Token 流
- **职责：** 将源代码字符序列分解为有意义的词法单元（Token），包括关键字、标识符、字面量、运算符、分隔符等。同时处理注释剥离和空白符跳过。
- **源码位置：** `src/Lex/`
- **关键处理：** 条件编译指令在此阶段被识别

### 2. Parse（语法分析）

- **输入：** Token 流
- **输出：** 抽象语法树（AST）
- **职责：** 根据仓颉语言的文法规则，将 Token 流组织为层次化的 AST 结构。此阶段进行语法正确性验证，并报告语法错误。宏展开（Macro Expansion）在此阶段触发。
- **源码位置：** `src/Parse/`
- **关键处理：** 宏调用在语法分析过程中被识别并展开

### 3. Sema（语义分析）

- **输入：** 未标注类型的 AST
- **输出：** 带类型标注的 AST（Typed AST）
- **职责：** 对 AST 进行全面的语义检查，包括：
  - 类型推断与类型检查
  - 名称解析与作用域分析
  - 重载决议
  - 泛型实例化
  - 访问控制检查
  - 模块导入解析（依赖 Modules 模块）
- **源码位置：** `src/Sema/`
- **关键依赖：** Modules（包/导入管理）、Mangle（符号修饰）

### 4. CHIR（高级中间表示生成）

- **输入：** 带类型标注的 AST
- **输出：** 优化后的 CHIR（Cangjie High-level IR）
- **职责：** 将带类型的 AST 转换为仓颉高级中间表示。CHIR 是一种比 AST 更接近执行语义的表示形式，便于进行高级优化。此阶段执行的优化包括：
  - 控制流简化
  - 高级别的代码变换
  - 语言特性的降级处理
- **源码位置：** `src/CHIR/`

### 5. CodeGen（代码生成）

- **输入：** 优化后的 CHIR
- **输出：** LLVM IR
- **职责：** 将 CHIR 翻译为 LLVM IR。此阶段负责：
  - 将仓颉类型映射到 LLVM 类型
  - 生成函数体的 LLVM IR 指令
  - 处理运行时调用的生成
  - 符号名称修饰（依赖 Mangle 模块）
- **源码位置：** `src/CodeGen/`
- **关键依赖：** Mangle（符号修饰）

### 6. LLVM Backend（LLVM 后端）

- **输入：** LLVM IR
- **输出：** 目标平台的目标文件或可执行文件
- **职责：** 由 LLVM 基础设施完成底层优化和机器代码生成，包括：
  - LLVM 优化 Pass（O0/O1/O2/O3）
  - 指令选择
  - 寄存器分配
  - 目标代码发射
  - 链接

## 支撑流程

以下系统在管线的多个阶段中发挥作用：

| 支撑系统 | 介入阶段 | 说明 |
|---------|---------|------|
| Macro | Parse | 编译期宏在语法分析阶段展开 |
| Modules | Sema | 包和导入在语义分析阶段解析 |
| Mangle | Sema, CodeGen | 符号修饰在语义分析和代码生成阶段使用 |
| ConditionalCompilation | Lex, Parse | 条件编译在词法和语法分析阶段处理 |
| IncrementalCompilation | 全阶段 | 增量编译跨越所有阶段管理缓存 |
| Driver | 全阶段 | 驱动器协调整个编译管线的执行 |

## 错误处理

每个阶段都可能产生诊断信息（错误、警告）。当某阶段检测到致命错误时，编译管线会在适当的时机终止，并向用户报告已收集的所有诊断信息。
